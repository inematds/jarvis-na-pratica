Never rented a server? Search for “VPS” (virtual private server) with any provider, choose Ubuntu (a Linux operating system), and note the address (a number like 203.0.113.10), username, and password they give you.

How to connect: On Windows, open Terminal (or PowerShell); on Mac, open Terminal. Type ssh user@address (for example, ssh root@203.0.113.10), press Enter, then type the password. That’s it: commands you type now run on the server. This remote terminal connection is called SSH.

How it works

The brain thinks. Jarvis handles the rest.

Think of a company: the brain is the employee you hire, and Jarvis is the office, with the rules on the wall. Replacing the employee doesn’t change the rules.

You ask→Jarvis adds memory and rules→the brain decides→the safety lock checks→it runs in a sandbox→answer

🧠 The brain only decides

It receives the conversation and says, “I want to check the disk” or “I want to delete the logs folder.” It doesn’t touch anything on the machine.

🔒 Jarvis owns the safety lock

It works like a gatekeeper for commands that affect the machine: commands that only look (check disk space, list folders) go straight through; any other command waits for your approval; commands with no undo (shutting down or restarting the machine, deleting everything, acting as an administrator) are blocked even if you approve. Any file you ask it to create or edit stays inside the work folder.

📦 The sandbox

Approved commands run in a box with no internet access, restricted to the work folder (a program called Docker creates this box). If something goes wrong, it stays inside.

📒 Memory and logs

What you ask Jarvis to remember is stored in Jarvis, not the AI. Every command, approved or not, is recorded in a log.

💬 What using it is like

Through Telegram on your phone: you send a message, Jarvis replies, and when you ask it to change something, it asks, “Posso rodar este comando?” (May I run this command?) and waits for your /sim (yes) or /nao (no). You can also use the command screen on the machine itself (the terminal), in the same way. See Using Telegram.

⚠️ What this doesn’t promise

Jarvis doesn’t read your email, WhatsApp, or other computer folders. In the sandbox, it can only see the work folder. It doesn’t make any AI smarter: a weak brain can still give the wrong answer. What the safety lock guarantees is protection: even when Jarvis makes a mistake, it won’t delete or restart anything without passing the safety check. We ran one test round per brain on one server; times vary from day to day.

Using Telegram

Talk to Jarvis from your phone

Jarvis lives on your computer or server, and you can talk to it through Telegram from anywhere. Only people on your owner list can talk to it; everyone else is ignored.

1. Create your bot

In Telegram, open @BotFather (the official bot that creates bots), send /newbot, and choose a name. It gives you a token: your bot’s key, a long code. Keep it safe and don’t show it to anyone: whoever has the token controls your bot.

2. Ask your AI to connect it

Tell your AI (the same one from “Getting started”): "turn on Jarvis in practice's Telegram mode, but don't ask me for the token in the chat" (Turn on Jarvis in Practice’s Telegram mode, but don’t ask me for the token in the chat). It creates the configuration file and gives you a command like nano .env, which opens that file in the server terminal. Paste the token there (in the terminal, paste with Ctrl+Shift+V or right-click), save with Ctrl+O and Enter, exit with Ctrl+X, and the AI starts the service. It restarts automatically if the machine reboots.

Never paste the token into a conversation with the AI or any chat.

3. Set yourself as the owner

Send /id to your bot. It replies with your Telegram ID. The AI adds that number to the owner list. Before then, the bot won’t reply to anyone.

4. Chat and switch AIs whenever you like

Just send a request as usual. Before making a change, it asks and waits for /sim or /nao (2 minutes; /yes and /no also work). To see which brain is thinking, send /cerebro. To switch, send /cerebro claude, /cerebro codex, or /cerebro openrouter (pay per use). The memory and safety lock stay.

What we verified: with a simulated Telegram account, outsiders are ignored and logged (even when the owner is registered); the owner gets through; deleting asks for approval; /nao keeps the folder; /sim deletes it; and switching brains remembers what was said earlier. On real Telegram, our test bot connected to the server and identified itself (record in results); we have not yet tested a real conversation from a phone.

Common questions

Before you get started

Do I need to know how to code?

No. Paste the prompt, read the plan the AI shows you, and say yes or no. The AI handles the installation.

How much does it cost?

The project is free. With Claude Code or Codex, use the subscription you already have. With OpenRouter, you pay only for what you use, in cents.

Do I need all three brains?

No. One is enough. The three options let you switch whenever you want.

Will it work on my Windows PC or Mac?

We tested it on a Linux server. In step 1 of “Getting started,” your AI checks your machine and tells you if it will work.

Could the AI delete something without me seeing?

Not through this setup. The brain doesn’t run anything: Jarvis does, after the safety check. Every command that does more than look waits for your approval; actions with no undo are blocked; and files it creates stay in the work folder.

Does it work through Telegram?

Telegram mode is ready. We tested it with 7 simulated Telegram tests (with the owner registered, outsiders are ignored and logged; the owner gets through; deleting asks for approval; /nao keeps the folder; /sim deletes it; switching brains preserves memory) and connected the real bot to our server, where it identified itself to Telegram. A real conversation from a phone is the next test. We measured the three brains through the terminal. See Using Telegram.
